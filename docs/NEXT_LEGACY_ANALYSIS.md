# Следующий этап: анализ legacy

На первом этапе создан технический каркас Symfony 8.1 и React SPA. Исходники прежней системы пока не предоставлены, поэтому предметная модель, соответствие Laravel → Symfony, порядок переноса функций и стратегия переключения трафика сейчас не определяются.

Для второго этапа в корень репозитория добавляется папка `legacy`. В ней ожидаются:

```text
legacy/
├── ...                    # Laravel-приложение и его рабочая структура
└── symfony-api/            # предыдущая проба переноса, если она существует
```

Дампы схемы, обезличенные примеры данных, конфигурационные шаблоны и документация могут находиться рядом. Реальные секреты, токены, персональные данные и production-дампы не должны попадать в Git. Рабочий production DSN не нужен для первичного статического анализа.

## Что нужно извлечь из исходников

| Область | Сведения для анализа |
| --- | --- |
| Среда и зависимости | Версии PHP/Laravel, Composer lock, frontend tooling, расширения PHP, фоновые процессы, сборка и deployment |
| HTTP-контракт | Маршруты, middleware, форматы запросов/ответов/ошибок, коды статуса, пагинация, публичные и закрытые endpoints |
| Данные | Migrations и фактическая схема, ключи, ограничения, индексы, связи, объёмы, кодировки, временные зоны и денежные типы |
| Поведение | Контроллеры, сервисы, модели, observers/events, валидаторы, политики доступа и скрытые побочные эффекты |
| Авторизация | Guards, сессии/токены, роли, правила доступа, recovery flows и границы персональных данных |
| Async и расписание | Jobs, очереди, retries, failed jobs, cron/scheduler, идемпотентность, конкурентное выполнение и транзакционные границы |
| Кэш и поиск | Ключи и TTL, invalidation, используемые Redis stores, SQL-поиск/индексы, hit ratio и измеренные узкие места |
| Внешние интеграции | Shopify и другие реально используемые сервисы, webhooks, подписи, rate limits, таймауты и направление синхронизации |
| Файлы и frontend | Хранилища и URL медиа, доступность файлов, frontend-маршруты, SEO, зависимости интерфейса от текущего API |
| Эксплуатация | Логи и наблюдаемость, известные сбои, backup/restore, секреты, deployment topology и реальные нагрузки |
| Проверки | Существующие тесты, контрактные проверки, воспроизводимые ошибки, команды запуска и пробелы покрытия |
| `legacy/symfony-api` | Выполненные переносы, принятые решения, незавершённые части, расхождения с Laravel и пригодность к Symfony 8.1 |

Для каталога отдельно потребуется установить фактическое количество записей, вариативность, атрибуты и фильтры, типы сортировок, требования поиска, частоту обновлений, источники импорта и допустимую задержку обновления данных. Эти сведения не заменяются демонстрационными сущностями или синтетическим миллионом товаров в основном окружении.

## Результат анализа второго этапа

После предоставления исходников нужно подготовить проверяемую карту текущего поведения: связи маршрутов с кодом и таблицами, владельцев данных, контракты интеграций, фоновые процессы и подтверждённые проблемы. Каждое утверждение должно опираться на конкретный файл/строку, схему, тест или измерение; предположения и отсутствующие сведения отмечаются отдельно.

Только после этой инвентаризации можно сравнить бизнес-контракты с новым каркасом, выбрать порядок переноса, сформулировать совместимость и критерии приёмки. Также отдельно определяются безопасное воспроизведение окружения, допустимые тестовые данные и необходимые контрактные/регрессионные проверки.

Этот документ перечисляет входные сведения для анализа. Он не утверждает, что прежняя схема или предыдущая проба Symfony подходят новой системе, и не задаёт заранее план переноса неизвестной бизнес-логики.
